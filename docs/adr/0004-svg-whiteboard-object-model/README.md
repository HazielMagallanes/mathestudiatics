# ADR 0004: SVG whiteboard with an object model

- **Status:** Accepted
- **Date:** 2026-09-27
- **Deciders:** Haziel Magallanes

## Context

The platform needs a "paper-like" solving surface that is comfortable on a
laptop (keyboard/mouse) and usable on a phone/tablet with touch or stylus. The
requirements were: freehand ink, simple shapes, text, **typed formulas**, undo/redo,
grid/axes, zoom/pan, PNG/SVG export, autosave, and full keyboard operability of
every action.

Alternatives considered:

1. **Canvas 2D with a pixel buffer** — fast to draw, but undo/redo, selection,
   moving objects and typed formulas all become hard; export needs re-rendering.
2. **Third-party whiteboard library** (Excalidraw/tldraw) — heavy dependency,
   opinionated UX, and it hides the parts we want to own (math objects, a11y,
   bundle budget).
3. **SVG with an object model** (chosen): every stroke/shape/text/math object is
   data; rendering is declarative; hit-testing is plain geometry.

## Decision

- Keep the board as a **pure data model** (`model/board.ts`, `history.ts`,
  `geometry.ts`, `stroke.ts`, `serialization.ts`) with no DOM dependencies, so it
  is unit-tested directly.
- Render with **SVG**: strokes become filled paths generated by
  `perfect-freehand` (pressure-sensitive ink), shapes are primitives, text is
  `<text>`, and formulas are KaTeX HTML inside `<foreignObject>`.
- Persist the model as versioned JSON validated with **zod**; store it in
  IndexedDB (debounced autosave) and export it as **SVG** (vector, always works)
  or **PNG** (rasterised from the SVG, with SVG fallback on failure).
- Provide **two equal input paths**: pointer (mouse/touch/stylus) and
  keyboard/typed (tool shortcuts, nudge/duplicate/delete, and a LaTeX scratchpad
  with live preview plus a symbol palette).

## Consequences

**Positive**

- Undo/redo, selection, moving and typed math are all straightforward because the
  board is data, not pixels.
- The model is tested without a browser; the E2E suite covers real pointer input.
- Self-contained: no third-party board, no network, no tracking.

**Negative / accepted tradeoffs**

- SVG with thousands of objects would need virtualization; fine for a study
  board (hundreds), documented as a future optimisation.
- `<foreignObject>` rasterisation is not supported by every browser; PNG export
  falls back to SVG.
- Resizing selected objects and rotation are not implemented yet (move, nudge,
  duplicate, delete, reorder are).

**Supersedes / Superseded by:** none.
